# Case Study: Entreprenuity Smart Website, Kerry, and Digital Ambush

## What We Built

Entreprenuity started with a conventional commercial website and evolved into a **custom Smart Website platform** built around AI-assisted customer interaction, automation, and prospect-specific workflows.

Rather than bolting a generic chatbot onto an off-the-shelf site, the Smart Website uses a custom React/Vite codebase, serverless API routes, AI integrations, analytics, and business workflows designed specifically around Entreprenuity's operating model.

The codebase was built under my direction using AI-assisted engineering. I defined the product, architecture, workflows, acceptance criteria, and operating rules; used AI coding agents to accelerate implementation; reviewed the resulting code and runtime behaviour; and iterated the system based on real testing.

## Smart Website Architecture

The system combines:

- Custom React/Vite frontend
- TypeScript/JavaScript application code
- Serverless API routes
- AI concierge behaviour through Kerry
- Prospect-aware AI context
- Lead and revision-request workflows
- Persistent visitor/chat context patterns
- Analytics and conversion instrumentation
- Secure public/private assistant boundaries
- Vercel deployment and preview workflows
- Responsive/mobile QA
- Integration points for agent and business automation workflows

## Kerry: AI Employee Inside the Website

Kerry is the customer-facing AI business guide embedded into the Smart Website.

The engineering problem is much broader than displaying a chat widget. Kerry must receive bounded business context, understand which prospect or customer she is speaking to, maintain useful conversation state, avoid exposing private infrastructure, and connect conversation intent to real business actions.

Work around Kerry has included:

- LLM/provider integration
- Prospect-aware prompt and context routing
- Conversation-history handling
- Queue/status and response patterns
- Safe visual homepage-concept artifacts
- Lead and booking/gatekeeper routing concepts
- Context persistence
- Telegram/agent notification patterns
- Separate behaviour for public website visitors and Digital Ambush prospects

## Digital Ambush

Digital Ambush is a reusable personalised-prospect system built on top of the Smart Website.

Instead of sending a generic cold-sales page, the workflow is designed to research a real business, create a prospect-specific concept, explain the reasoning, let the prospect interact with an AI guide, and capture what happens next.

The pattern combines:

- Evidence-backed prospect research
- Business-specific homepage concepts
- Current-versus-proposed visual framing
- Trade-specific questions
- AI-guided explanation of design decisions
- Engagement telemetry
- Prospect-specific conversation context
- Revision-request capture
- Repeatable per-prospect operating rules
- Clear separation between verified evidence, illustrative scenarios, and proposed outcomes

A core rule is that the system must not fabricate rankings, traffic, revenue loss, testimonials, or performance gains just to make the sales page sound stronger.

## Agent Integration

The longer-term Smart Website architecture is designed to connect the customer-facing website to the broader NEO/OpenClaw operating layer so website conversations and business events can become structured work for AI agents rather than disappearing into an inbox.

That means the website becomes an operating interface, not just a brochure.

Examples of the direction include:

- AI receptionist and enquiry handling
- Lead follow-up
- Research and prospect preparation
- Customer context handoff
- Revision and design requests
- Notifications and human approval gates
- CRM/task workflow integration
- Agent-triggered business operations
